# Audio Scene Generator - Lightweight Website Features

This document outlines the planned features to upgrade the project into a simple, lightweight, Python-only local website. The focus is on keeping the architecture as simple as possible while adding basic social features, an admin dashboard, and an interactive audio player.

## 1. Tech Stack (Keep It Simple)
*   **Backend:** Python web framework (like Flask or FastAPI) to keep it strictly Python-based.
*   **Database & Auth:** SQLite (a simple local file database, e.g., `app.db`). Basic username and password login using session cookies.
*   **File Storage:** Local filesystem (e.g., a `/static/audio/` folder). Generated audio files are saved locally and served directly to the web page.
*   **Frontend:** HTML, CSS, and vanilla JavaScript. No complex frameworks.

## 2. Core Features & UI
*   **Simple Authentication & Admin Dashboard:**
    *   Basic user login and registration.
    *   **Admin Dashboard:** A private page where an admin can view all users, manage access, and monitor all generated audiobooks.
*   **Social Following & Feed:**
    *   Users can click to "Follow" other users.
    *   A Home Feed that displays audiobooks generated by the people you follow, allowing you to listen to their creations.
*   **Interactive Audio Player (The Star Feature):**
    *   When an audiobook plays, the UI visually displays the characters in the scene.
    *   **Avatars:** Uses simple, properly gendered placeholder icons (e.g., a default male icon and a default female icon).
    *   **Talking Waveform:** Using simple JavaScript and the generated timeline data, a live audio waveform appears below the character's icon *only* when it is their turn to speak.
*   **"Create Audio Book" Wizard:**
    *   A clean, streamlined page requiring just simple clicks and a short text prompt. also keep templates for each kind of story theme and add a bacground image to it generated using ai.
    *   The system generates a "short and sweet" story (not too long, not too short) and handles all the audio generation behind the scenes automatically.

## 3. Simplified Database Data Model (SQLite)
*   **Users:** ID, Username, PasswordHash, IsAdmin.
*   **Follows:** Follower_ID, Followed_ID.
*   **AudioBooks:** ID, User_ID, Title, FilePath (local path), TimelineData (JSON mapping who speaks when, used by the frontend to trigger the waveforms).

## 4. Project Goals
*   **Lightweight:** The website must load fast, avoid bloat, and run smoothly on a local machine.
*   **Simplicity:** No complex cloud setups, no heavy background task queues, and no random bloated features. Just a clean, fun, social local app.
